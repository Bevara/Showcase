Opening your own browser to new formats

Every other demo on this site asks the page to carry the decoder: the markup names a solver and a set of accessors, and the page works for everyone who visits it. This one asks nothing of the page. The markup below is plain HTML — ordinary <img>, <audio> and <video> tags, no Bevara attributes, no scripts, no WebAssembly — exactly what a site that never heard of Bevara would write:

<img src="testcard.psd">
<audio src="testcard.gsm" controls></audio>

So, in a stock browser, most of this page is broken. Install the Bevara Universal Media extension and it is not: the extension watches the page, notices each element the browser cannot decode, and hands it to a WebAssembly pipeline fetched from the Bevara filter registry, which gives the browser back a format it does play — PNG for images, WAV for audio, MP4/H.264 for video.

Install from the Chrome Web Store Chrome, Edge, Brave and other Chromium browsers. Then reload this page.

Video

Video is different from a picture or a sound: whatever the source format, the result has to be re-encoded into something the browser plays. The only encoder for that is H.264, whose patents are pooled — so rather than download a patent-encumbered encoder, the extension hands the job to the one your browser already ships, through WebCodecs. Nothing encumbered is fetched, and these play with the extension's default settings.

Ogg / Theora

Decoded by theora_1, re-encoded by your browser. Chrome dropped Theora in version 123, so without the extension this shows a player that never paints a picture.

Dirac

A raw Dirac elementary stream, no container at all. No browser reads it.

Two limits worth knowing. The re-encoded video has no sound — the solver cannot yet put an audio track through WebCodecs. And a long source comes out truncated: the session is cut short while the encoder is still working, so the clips here are deliberately short. Formats whose decoder is itself patent-encumbered — HEVC, VVC, AV1, VP9, AVS, EVC — stay out of reach until you allow encumbered accessors in the options.

Anything it declined to touch is listed too, with the reason — a decoder not published, or a patent status you have not allowed.

How it works

This is the MutationObserver approach of the companion demo, moved out of the page and into the browser. A content script watches the DOM; for each <img>, <audio> and <video> it identifies the format from the MIME type, the extension, or the file's first bytes, and asks canPlayType() whether the browser can cope. A format no browser decodes is taken over at once; a format the browser might decode is left alone until it actually fails, so the browser always gets the first try.

The accessors are not bundled in the extension: the catalogue and the modules come from the registry, which means a format published there becomes playable without updating the extension.

The source of the extension, and the three ways of integrating these pipelines into a page, are described in the documentation.
